# Agent Skills (`skills`)

Uses the [`skills` CLI](https://github.com/vercel-labs/skills#readme) to fetch agent skills during the image build and copy them into the configured container user's global agent directories.

```json
{
    "features": {
        "ghcr.io/kubamarchwicki/devcontainer-features/skills:1": {
            "sources": "vercel-labs/skills@find-skills,vercel-labs/agent-skills@web-design-guidelines",
            "agents": "codex,claude-code"
        }
    }
}
```

## Options

| Option | Default | Description |
| --- | --- | --- |
| `sources` | `""` | Comma- or newline-separated sources. Empty installs no skills. Use `owner/repo` for every skill in a repository or `owner/repo@skill-name` for one. Repository and tree URLs, including URLs pinned to a source revision, are passed through unchanged. |
| `agents` | `codex,claude-code` | Comma- or whitespace-separated agent IDs, or `*` for every agent the CLI supports. See the [`skills` README](https://github.com/vercel-labs/skills#readme) for current IDs. |
| `version` | `latest` | npm version or tag of the `skills` CLI. Separate from any revision pinned in a skill source. |

## Behavior

The Feature always requests global, independent copies rather than symbolic links. The CLI owns destination mapping; with `skills@1.5.25`, Codex receives copies in `~/.agents/skills` and Claude Code in `~/.claude/skills`. Skills are installed into the build-time remote user's home with that user as owner. Rebuild the container to apply configuration changes.

## Requirements and caveats

- Depends on `ghcr.io/devcontainers/features/node:1` for a current Node.js runtime, and installs Git and CA certificates when Git is missing. The Git bootstrap recognizes `apt-get`, `apk`, and `dnf` when the Node dependency supports the selected base.
- Tested on Ubuntu and the Debian-compatible Dev Containers base; overall operating-system support follows the standard Node Feature.
- Declaring the Node Feature separately with different options may cause the Dev Container CLI to install two Node Feature instances.
- Use a login name rather than a numeric UID for `remoteUser` or `containerUser`. The runner resolves either form, but the standard Node Feature rejects numeric IDs before this Feature runs.
- Private sources need credentials available during the image build.
- A bind mount or volume over the target home or skills directory can hide skills installed in the image.

## Testing

```sh
devcontainer features test --project-folder . --features skills --skip-autogenerated
```

The matrix covers root and non-root installation, default and overridden agents, selected skills, whole repositories, repeated installation, and empty configuration. The root, remote-user, and empty scenarios omit `version` to exercise the `latest` default; the Claude-only and whole-repository scenarios pin the CLI version.
