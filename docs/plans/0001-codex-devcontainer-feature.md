# Codex Dev Container Feature Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create a locally testable, single-Feature collection that installs the Codex CLI globally from npm without managing authentication, Codex state, mounts, editor integration, or container privileges.

**Architecture:** The collection contains one `codex` Feature. Its POSIX installer reuses an existing `node` and `npm` pair or bootstraps the distribution's `nodejs` and `npm` packages through `apt-get`, `apk`, or `dnf`, then passes the unvalidated `version` option directly to npm. Four native-architecture Dev Container scenarios cover Ubuntu, Alpine, Amazon Linux 2023, and reuse of the standard Node Feature.

**Tech Stack:** POSIX shell, Dev Container Feature JSON, npm package `@openai/codex`, Dev Container CLI, Docker

## Global Constraints

- The public target reference is `ghcr.io/kubamarchwicki/devcontainer-features/codex:1`; publishing automation is outside this plan.
- The Feature version is `1.0.0`. The Codex package version is a separate, opaque npm selector exposed as `version`, defaulting to `latest`.
- Install Codex with exactly `npm install --global --engine-strict "@openai/codex@${VERSION}"`; do not add a custom npm prefix.
- Always run the npm installation, even when a `codex` executable already exists.
- Reuse existing `node` and `npm` only when both are present. Otherwise install the distribution's `nodejs` and `npm` packages.
- Use only configured distribution repositories through `apt-get`, `apk`, or `dnf`. Do not add NodeSource, pin a Node major, or add `yum`.
- Do not install a second, distribution-owned `ripgrep`. The selected `@openai/codex` package owns its bundled search binary; shell-wide `rg` is outside this Feature's contract.
- Include soft ordering after `ghcr.io/devcontainers/features/node`; do not require consumers to declare that Feature.
- Do not manage authentication, API keys, `CODEX_HOME`, `~/.codex`, mounts, editor extensions, ownership, capabilities, security options, or privileged mode.
- The only installer-level post-install verification is `codex --version`.
- Keep all scenario scripts compatible with `/bin/sh`, including Alpine.
- Use `--skip-autogenerated` for local tests. The autogenerated Dev Container test uses Ubuntu Focal, which is outside the agreed four-image matrix and conflicts with the native-package policy.
- Do not add validation, test, release, or publishing workflows in this phase.

- [ ] **Step 3: Generalize the installer to apt-get, apk, and dnf**

Replace `src/codex/install.sh` with:

```sh
#!/bin/sh
set -eu

VERSION="${VERSION:-latest}"

detect_package_manager() {
    for candidate in apt-get apk dnf; do
        if command -v "${candidate}" >/dev/null 2>&1; then
            printf '%s\n' "${candidate}"
            return 0
        fi
    done
    return 1
}

install_nodejs() {
    package_manager="$1"

    case "${package_manager}" in
        apt-get)
            apt-get update
            DEBIAN_FRONTEND=noninteractive \
                apt-get install -y --no-install-recommends nodejs npm
            ;;
        apk)
            apk add --no-cache nodejs npm
            ;;
        dnf)
            dnf install -y nodejs npm
            ;;
        *)
            printf 'ERROR: Unsupported package manager: %s\n' "${package_manager}" >&2
            exit 1
            ;;
    esac
}

ensure_nodejs() {
    if command -v node >/dev/null 2>&1 && command -v npm >/dev/null 2>&1; then
        return 0
    fi

    if ! package_manager="$(detect_package_manager)"; then
        printf '%s\n' \
            'ERROR: Node.js and npm are missing, and no supported package manager was found.' >&2
        exit 1
    fi

    install_nodejs "${package_manager}"

    if ! command -v node >/dev/null 2>&1 || ! command -v npm >/dev/null 2>&1; then
        printf '%s\n' 'ERROR: Failed to install Node.js and npm.' >&2
        exit 1
    fi
}

ensure_nodejs
npm install --global --engine-strict "@openai/codex@${VERSION}"
codex --version
```

````markdown
# Codex Dev Container Feature

A single Dev Container Feature that installs the OpenAI Codex CLI globally from npm.

## Usage

The target published reference is:

```json
{
    "features": {
        "ghcr.io/kubamarchwicki/devcontainer-features/codex:1": {}
    }
}
```

Pin an npm version, tag, or other npm selector with the `version` option:

```json
{
    "features": {
        "ghcr.io/kubamarchwicki/devcontainer-features/codex:1": {
            "version": "0.145.0"
        }
    }
}
```

`version` defaults to `latest` and is passed to npm without Feature-level validation.

## Node.js bootstrap

If both `node` and `npm` already exist, the Feature reuses them. If either is missing, it installs the distribution's `nodejs` and `npm` packages through `apt-get`, `apk`, or `dnf`.

The Feature uses configured distribution repositories. It does not add NodeSource or pin a Node.js major. If a consumer already declares `ghcr.io/devcontainers/features/node`, soft ordering installs that Feature first.

The Feature does not install a separate distribution copy of `ripgrep`; runtime resources bundled by the selected `@openai/codex` package remain package-owned.

## Security, state, and authentication

The Feature installs only the Codex CLI. It does not:

- mount or copy `~/.codex` or `CODEX_HOME`;
- configure API keys or perform login;
- install an editor extension;
- request privileged mode, capabilities, or security options.

Authenticate at runtime using the Codex CLI or your own environment and secret-management setup.

## Local testing

With Docker and the Dev Container CLI installed:

```sh
devcontainer features test --project-folder . --features codex --skip-autogenerated
```

The matrix covers `ubuntu:24.04`, `alpine:3.23`, `amazonlinux:2023`, and the standard Node Feature on the current Docker architecture.

The project is licensed under the [MIT License](LICENSE).
````
