# Release Workflows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add GitHub Actions that validate and scenario-test the Codex Feature and publish it to GHCR from `master`.

**Architecture:** Mirror the three workflows from `anthropics/devcontainer-features` at commit `4c6fe6a383af8adf71b4b22fd868aaf18b5272b1`. Adapt the default branch from `main` to this repository's `master`, adapt the Feature id from `claude-code` to `codex`, and reduce the test workflow to the upstream `test-scenarios` job because this repository intentionally relies on its explicit four-scenario matrix. The release workflow publishes only: it omits generated documentation, pull-request permissions, and the upstream documentation-PR step.

**Tech Stack:** GitHub Actions, `devcontainers/action@v1`, `@devcontainers/cli`, GitHub Container Registry

**Upstream source:**

- `https://github.com/anthropics/devcontainer-features/blob/4c6fe6a383af8adf71b4b22fd868aaf18b5272b1/.github/workflows/release.yaml`
- `https://github.com/anthropics/devcontainer-features/blob/4c6fe6a383af8adf71b4b22fd868aaf18b5272b1/.github/workflows/test.yaml`
- `https://github.com/anthropics/devcontainer-features/blob/4c6fe6a383af8adf71b4b22fd868aaf18b5272b1/.github/workflows/validate.yaml`

## Global Constraints

- Preserve the upstream workflow contents from commit `4c6fe6a383af8adf71b4b22fd868aaf18b5272b1` except for the explicit adaptations listed below.
- Normalize upstream trailing whitespace and final newlines; do not otherwise reformat or rewrite the workflow files.
- Replace upstream branch `main` with this repository's default branch `master` everywhere it controls triggers, deployment guards, API lookups, or pull-request targets.
- Replace upstream Feature id `claude-code` with `codex`.
- Keep only the upstream `test-scenarios` job in `test.yaml`; do not add `test-autogenerated` or `test-global`.
- Keep `continue-on-error: true` on `test-scenarios`, matching upstream.
- Keep the scenario command exactly `devcontainer features test -f ${{ matrix.features }} --skip-autogenerated --skip-duplicated .`.
- Preserve the upstream action versions exactly: `actions/checkout@v4` and `devcontainers/action@v1`.
- Preserve the upstream release triggers and Feature publishing behavior, but omit the complete `Create PR for Documentation` step.
- Do not enable `generate-docs`; without a documentation pull request, generated working-tree files have no release output.
- Publish from `master` with only `contents: write` and `packages: write` through the workflow-provided `GITHUB_TOKEN`; do not grant `pull-requests: write` and do not add repository secrets.
- Do not add concurrency controls, environments, attestations, custom registries, action-SHA pinning, release tags, changelog generation, or any workflow not present upstream.
- Do not modify the Feature implementation, tests, README, license, context, or ADRs.

- [ ] **Step 2: Add the scenario-only test workflow**

Create `.github/workflows/test.yaml`:

```yaml
name: "CI - Test Features"
on:
  push:
    branches:
      - master
  pull_request:
  workflow_dispatch:

jobs:
  test-scenarios:
    runs-on: ubuntu-latest
    continue-on-error: true
    strategy:
      matrix:
        features:
          - codex
    steps:
      - uses: actions/checkout@v4

      - name: "Install latest devcontainer CLI"
        run: npm install -g @devcontainers/cli

      - name: "Generating tests for '${{ matrix.features }}' scenarios"
        run: devcontainer features test -f ${{ matrix.features }} --skip-autogenerated --skip-duplicated .
```


Expected: non-zero exit because the release workflow is new.

- [ ] **Step 2: Add the release workflow**

Create `.github/workflows/release.yaml`:

```yaml
name: "Release Dev Container Features"

on:
  push:
    branches:
      - master
  workflow_dispatch:

jobs:
  deploy:
    if: ${{ github.ref == 'refs/heads/master' }}
    runs-on: ubuntu-latest
    permissions:
      contents: write
      packages: write
    steps:
      - uses: actions/checkout@v4

      - name: "Publish Features"
        uses: devcontainers/action@v1
        with:
          publish-features: "true"
          base-path-to-features: "./src"

        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```
